### Work Item 4.1: Policy Audit (REQ-SEC-07)

**Goal:** Review all 4 policy objects for authorization gaps. Fix identified issues. Write extended tests.

#### Gap Analysis

| Policy | Current State | Gaps | Fix |
|--------|---------------|------|-----|
| **ProductPolicy** | `canView(null, product)` has unsafe `user!` assertion — crashes on null user for inactive product | Add null check: if user is null, return `product.isActive` only. |
| **OrderPolicy** | No `canCancel()` method | Add `canCancel(user, order)` — cancellable in pending/confirmed states |
| **SellerProfilePolicy** | No `canCreate()` check — any role could create profile | Add `canCreate(user)` checking `user.role === UserRole.SELLER \|\| isAdmin(user)` |

| `backend/src/auth/policies/order.policy.ts` | Add `canCancel(user, order)` method |

#### Files to Create

#### Implementation Notes

```typescript
// product.policy.ts — fixed canView
canView(user: User | null, product: ProductLike): boolean {
  if (product.isActive) return true;
  if (!user) return false;
  if (this.isAdmin(user)) return true;
  const ownerId = product.sellerId ?? product.seller?.id;
  return user.id === ownerId;
}

// seller-profile.policy.ts — added canCreate
canCreate(user: User): boolean {
  if (this.isAdmin(user)) return true;
  return user.role === UserRole.SELLER;
}

// order.policy.ts — added canCancel
canCancel(user: User, order: OrderLike): boolean {
  if (this.isAdmin(user)) return true;
  const ownerId = order.userId ?? order.user?.id;
  if (user.id !== ownerId) return false;
  return order.status === 'pending' || order.status === 'confirmed';
}
```

#### Test Strategy

| Test | Approach | Command |
|------|----------|---------|
| ProductPolicy: null user can view active | `canView(null, activeProduct)` → true | `pnpm test -- product-policy-extended` |

| SellerProfilePolicy: non-seller cannot create | `canCreate(customerUser)` → false | `pnpm test -- seller-profile` |

| OrderPolicy: canCancel for pending | `canCancel(owner, { status: 'pending' })` → true | `pnpm test -- order-policy-extended` |

### Work Item 4.4: Remove RefreshTokenGuard from Non-Refresh Endpoints (MAJ-12)

**Goal:** The `RefreshTokenGuard` currently fires on `POST /auth/login` and `POST /auth/register` endpoints because the controller applies guards at class level. This means every login/register request re-validates the refresh token cookie unnecessarily. The guard should only protect the `POST /auth/refresh` endpoint.

**Fix:** Remove class-level `@UseGuards(RefreshTokenGuard)` from `AuthController`. Instead apply it only to the `refresh()` method. For `logout()`, use `JwtAuthGuard` (access token) instead of `RefreshTokenGuard`.

#### Files to Modify

| File | Required Changes |
|------|-----------------|
| `backend/src/auth/auth.controller.ts` | Remove class-level `@UseGuards(RefreshTokenGuard)`. Add `@UseGuards(RefreshTokenGuard)` only to `refresh()`. Change `logout()` to use `JwtAuthGuard`. Update `refresh()` to set new refreshToken cookie in response. |
| `backend/src/auth/guards/refresh-token.guard.ts` | No change needed. |

#### Implementation

```typescript
// auth.controller.ts — updated guard application
@Controller('auth')
export class AuthController {
  // login, register, forgotPassword, resetPassword — guards removed
  
  @Post('refresh')
  @UseGuards(RefreshTokenGuard)
  async refresh(@CurrentUser() user: { id: string; sessionId: string }, ...) { ... }
  
  @Post('logout')
  @UseGuards(JwtAuthGuard)
  async logout(@CurrentUser() user: TokenPayload, ...) { ... }
}
```

The `logout()` can receive an optional `sessionId` from request body or revoke all sessions for the user.

### Task 00-04-1: Verify server starts and no clocking remnants

<read_first>
- `.pam/server.js` — Server code (check for no clocking routes)
- `.pam/state.json` — State data (check for no clocking fields)
- `.pam/cli.sh` — CLI (check for no clocking commands)
- `.pam/dashboard.html` — Dashboard (check for no clock-in button/modal)
</read_first>

<action>
1. Start the server: `node .pam/server.js &`
2. Check server banner shows comments endpoints (not clocking)
3. Kill server

Run the following checks and record results:
```bash
# No clocking routes in server
grep -n "clock-in\|clock-out\|reset-week" .pam/server.js || echo "✓ No clocking routes in server.js"

# No clocking fields in state.json skeleton (if file exists)
grep -n "clock\|session\|logs" .pam/state.json || echo "✓ No clocking fields in state.json"

# No clocking commands in CLI
grep -n "clock-in\|clock-out\|clockin\|clockout\|CLOCKED" .pam/cli.sh || echo "✓ No clocking commands in cli.sh"

# No clock-in button or modal in dashboard
grep -c "Clock In\|clock-in\|toggleSession\|showClockInModal" .pam/dashboard.html && echo "⚠ Clocking references found in dashboard" || echo "✓ No clocking in dashboard.html"
```

If clocking remnants are found anywhere, report them as issues to fix.
</action>

<acceptance_criteria>
- Server starts without errors
- Server banner does NOT list clock-in/clock-out endpoints
- `grep` for clocking routes in server.js returns 0 matches
- `grep` for clocking fields in state.json returns 0 matches
- `grep` for clocking commands in cli.sh returns 0 matches
- `grep` for clocking in dashboard.html returns 0 matches (except possibly in non-functional CSS class names)
</acceptance_criteria>

### Task 00-04-2: API smoke test — comments and hours endpoints

<read_first>
- `.pam/server.js` — API endpoint handlers
- `.pam/comments.json` — Initial empty state
- `.pam/tasks.json` — Task data for referencing IDs
</read_first>

<action>
Start the server, then run these curl commands:

```bash
SERVER_PID=$!
sleep 1

echo "=== 1. GET /api/status (baseline) ==="
curl -s http://localhost:4747/api/status | head -c 200
echo ""

echo "=== 2. GET /api/comments (empty) ==="
curl -s http://localhost:4747/api/comments
echo ""

echo "=== 3. POST /api/comments (create) ==="
COMMENT=$(curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"task_id":"p1-auth-1","phase_id":"phase-1","text":"Test comment from verification","category":"question"}' \
  http://localhost:4747/api/comments)
echo "$COMMENT"
COMMENT_ID=$(echo "$COMMENT" | grep -o '"id":"[^"]*"' | cut -d'"' -f4)

echo "=== 4. PATCH /api/comments/$COMMENT_ID/read ==="
curl -s -X PATCH "http://localhost:4747/api/comments/$COMMENT_ID/read"
echo ""

echo "=== 5. POST /api/task/update with hours ==="
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"task_id":"p1-auth-2","status":"done","hours":1.5}' \
  http://localhost:4747/api/task/update | head -c 200
echo ""

echo "=== 6. GET /api/state (check task_hours) ==="
curl -s http://localhost:4747/api/state | grep -o '"task_hours":[^}]*'
echo ""
```

Record results. Flag any failures.
</action>

<acceptance_criteria>
- GET /api/status returns 200 with valid JSON
- GET /api/comments returns `{"comments":[]}` or valid comments array
- POST /api/comments returns 200 with `"id"` in response
- PATCH /api/comments/:id/read returns `{"success":true}`
- POST /api/task/update with hours returns 200
- GET /api/state shows `"task_hours":{"p1-auth-2":1.5}` after update
- OPTIONS request to PATCH endpoint returns 204 (CORS)
</acceptance_criteria>

# Plan 00-01: Backend API & Data Layer

## Objective

Refactor the PAM backend server to:
1. Remove clock-in/clock-out endpoints and simplify state.json
2. Add inline hours entry capability to task updates
3. Create the comments system: new JSON data store + CRUD API endpoints
4. Keep zero external dependency constraint (Node.js built-in modules only)

## Dependencies

- **Depends on:** None (Wave 1 — foundational)
- **Required by:** Dashboard UI (00-02), CLI tooling (00-03)

### Task 00-01-4: Add comments CRUD API endpoints to server.js

<read_first>
- `.pam/server.js` — Full file to understand route registration pattern, JSON read/write helpers
- `.pam/comments.json` — Just created in task 00-01-3
- `.planning/phases/00-pam-dashboard/00-CONTEXT.md` — D-21 through D-25 for comments behavior
</read_first>

<action>
Add the following API endpoints to `server.js` using the existing `route()` function:

1. **`GET /api/comments?task_id=X&phase_id=Y`** — Returns comments filtered by task_id and/or phase_id (both optional). If no filters: return all comments. Sorted by `created_at` descending.
   - Route: `route('GET', '/api/comments', handler)`
   - Parse URL query params for `task_id`, `phase_id`
   - Response: `{ success: true, comments: [...] }`

2. **`POST /api/comments`** — Create a new comment.
   - Accepts: `{ task_id, phase_id, text, category }`
   - Validates: `text` required (non-empty), `category` must be one of `bug|question|suggestion|note` (default `note`)
   - Auto-generates: `id` as `cmt-{padded counter}`, `created_at` as `new Date().toISOString()`, `read: false`, `resolved: false`
   - Response: `{ success: true, comment: { ... } }`

3. **`PATCH /api/comments/:id/read`** — Mark a comment as read.
   - Reads comment by `id`, sets `read: true`
   - Returns 404 if comment not found
   - Response: `{ success: true }`

4. **`PATCH /api/comments/:id/resolve`** — Mark a comment as resolved.
   - Sets `resolved: true`, `resolved_at: new Date().toISOString()`
   - Returns 404 if comment not found
   - Response: `{ success: true, comment: { ... } }`

Helper function `findCommentIndex(id)` to locate comments by ID in the array.

IMPORTANT: Add `'PATCH'` to the CORS allowed methods header on line ~285.
</action>

<acceptance_criteria>
- `curl -s http://localhost:4747/api/comments | grep '"success":true'` returns successfully
- `curl -s -X POST -H 'Content-Type: application/json' -d '{"task_id":"p1-auth-1","phase_id":"phase-1","text":"test comment"}' http://localhost:4747/api/comments | grep '"id":"cmt-1"'` returns successfully
- `curl -s -X PATCH http://localhost:4747/api/comments/cmt-1/read` returns `{"success":true}`
- After PATCH, reading comments shows `"read":true` for that comment
- OPTIONS preflight works for PATCH: `curl -s -X OPTIONS -H 'Access-Control-Request-Method: PATCH' http://localhost:4747/api/comments` returns 204
- `grep -c "PATCH" .pam/server.js` is non-zero (PATCH added to CORS header)
</acceptance_criteria>
